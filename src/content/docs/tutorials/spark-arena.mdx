title: Benchmark on Spark Arena
description: Submit benchmark results to the Spark Arena leaderboard and compare your DGX Spark performance with the community.
---

[Spark Arena](https://spark-arena.com) is a community leaderboard for DGX Spark inference performance. sparkrun integrates directly with Spark Arena — authenticate, benchmark, and submit results all from the CLI.

Use `sparkrun arena` for `login`, `logout`, and `status`. After logging in,
`sparkrun benchmark <recipe> --arena` runs the benchmark and submits its results:

1. **Launches** the inference server
2. **Benchmarks** using the standardized `@official/spark-arena-v2` profile
3. **Collects** results (CSV, metadata, effective recipe)
4. **Stops** the inference server launched for the benchmark
5. **Uploads** the submission to the Spark Arena leaderboard

## 1. Log in to Spark Arena

Before submitting benchmarks, authenticate with your Spark Arena account:

```bash
sparkrun arena login
```

This opens your browser for OAuth authentication. Sign in with your preferred provider (GitHub, Google, etc.) and sparkrun stores a refresh token locally.

:::tip[Headless or remote machines]
If you're running sparkrun on a headless server or over SSH, the login flow automatically falls back to a **device code flow** — it displays a URL and a code you can enter on any device with a browser.
:::

Verify your login status anytime:

```bash
sparkrun arena status
```

## 2. Run a Spark Arena benchmark

With authentication in place, run a benchmark and submit in one step:

```bash
sparkrun benchmark qwen3-1.7b-sglang --arena
```

This uses your default cluster. To target a specific cluster or hosts:

```bash
# Use a saved cluster
sparkrun benchmark qwen3-1.7b-sglang --arena --cluster mylab

# Or specify hosts directly
sparkrun benchmark qwen3-1.7b-sglang --arena --hosts 10.24.11.13,10.24.11.14
```

For multi-node benchmarks, set tensor parallelism:

```bash
sparkrun benchmark qwen3-1.7b-sglang --arena --tp 2
```

`--arena` enables Spark Arena submission and defaults to the standardized
`@official/spark-arena-v2` profile. You can use the same option with the explicit
`benchmark perf` subcommand. An explicit `--profile` takes precedence.

## 3. What gets submitted

When the benchmark completes, sparkrun uploads three files to Spark Arena:

| File | Contents |
|---|---|
| `recipe.yaml` | The effective recipe (with all overrides applied) |
| `benchmark.csv` | Raw benchmark results (prompt sizes, token counts, latencies, throughput) |
| `metadata.json` | System metadata — sparkrun version, cluster info, runtime details, container image |

All files are cached locally under `~/.cache/sparkrun/benchmarks/<submission-id>/` so you always have a copy.

## 4. Recipe overrides

You can apply the same recipe overrides as `sparkrun run`:

```bash
# Override GPU memory utilization
sparkrun benchmark qwen3-1.7b-sglang --arena -o gpu_memory_utilization=0.9

# Override max model length
sparkrun benchmark qwen3-1.7b-sglang --arena -o max_model_len=8192

# Override container image
sparkrun benchmark qwen3-1.7b-sglang --arena --image my-custom-image:latest
```

These overrides are captured in the submission metadata, so the leaderboard accurately reflects your exact configuration.

## 5. Resumable submissions

Long `@official/spark-arena-v2` sweeps are checkpointed after every benchmark task.
If a run is interrupted, use the same recipe and settings plus `--resume` to
continue without prompting, skipping completed tasks.

```bash
# First attempt — interrupted partway through
sparkrun benchmark qwen3-1.7b-sglang --arena --cluster mylab --tp 2

# Resume without prompting, then submit when complete
sparkrun benchmark qwen3-1.7b-sglang --arena --cluster mylab --tp 2 --resume
```

sparkrun also **pins the benchmarking framework version** (e.g. the `llama-benchy` release) on the first task of a run and reuses that exact version for every subsequent task — even after a resume — so the numbers you submit are internally consistent. The pinned version is captured in the uploaded `metadata.json`.

State files live under `~/.cache/sparkrun/benchmarks/`. See [Resumable runs](/tutorials/benchmarking/#8-resumable-runs) in the benchmarking tutorial for more detail.

## 6. Log out (optional)

Your credentials persist across sessions — you only need to log in once. If you want to remove stored credentials (e.g., switching accounts or on a shared machine):

```bash
sparkrun arena logout
```

## Publication recovery

Measurement completion is independent of upload success. Keep the saved benchmark
or submission reference after an interrupted upload; retry completed-state
publication without launching inference or remeasuring. Reacquire credentials at
execution time rather than embedding them in benchmark checkpoints. Resume the
saved benchmark by ID:

```bash
sparkrun benchmark resume <benchmark-id>
```

The saved run retains its Arena integration and submission ID, so this retries
publication without adding `--arena` again. See
[Benchmark API](/developer-reference/benchmark-api/#results-and-finalization-retry).
