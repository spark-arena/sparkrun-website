---
title: Creating Clusters
description: Create and configure named clusters for DGX Spark hosts.
---

Clusters are named logical groups of hosts, including a single host. Groups may
overlap; they do not partition the physical machines. Save all your nodes as the
default cluster, then add smaller groups when useful. Prefer cluster names over
explicit host lists for everyday commands. See
[Recommended Cluster Setups](/clusters/recommended-setups/) for one-, two-, four-,
and eight-node examples.

:::tip
New to sparkrun? Run `sparkrun setup wizard` for a guided walkthrough that creates your cluster, sets up SSH, configures networking, and more — all in one step.
:::

## Create a cluster

```bash
sparkrun cluster create mylab \
  --hosts 192.168.11.13,192.168.11.14 \
  --default \
  -d "My DGX Spark lab"
```

### Options

| Option | Description |
|---|---|
| `--hosts` / `-H` | Comma-separated list of host IPs or names |
| `--default` | Make this the default cluster for subsequent commands |
| `-d` / `--description` | Human-readable description |
| `--user` | SSH user for connecting to hosts |
| `--cache-dir` | Override HuggingFace cache directory for this cluster |
| `--transfer-mode` | Resource distribution mode: `auto` (default), `local`, `push`, `delegated` |
| `--transfer-interface` | Network interface for high-speed transfers between cluster hosts |

## Host ordering

The first host of the **scheduled placement** becomes head; occupancy scheduling can choose a different host from the first saved candidate. Host order still matters for greedy placement. Inspect the plan/status for the actual head.

```bash
# Save candidates; scheduling determines the actual head
sparkrun cluster create mylab --hosts 192.168.11.13,192.168.11.14
```

## SSH user

By default, sparkrun uses your current OS user for SSH. Set a per-cluster user:

```bash
sparkrun cluster create mylab \
  --hosts 192.168.11.13,192.168.11.14 \
  --user dgxuser
```

Or override per-command with `--user`.

## Transfer mode

```bash
sparkrun cluster create mylab \
  --hosts 192.168.11.13,192.168.11.14 \
  --transfer-mode delegated
```

Controls how container images and models are distributed to cluster hosts. Options: `auto` (default), `local`, `push`, `delegated`. See [Networking](/getting-started/networking/#resource-transfer-modes) for details on each mode.

## Cache directory

```bash
sparkrun cluster create mylab \
  --hosts 192.168.11.13,192.168.11.14 \
  --cache-dir /data/hf-cache
```

Override the HuggingFace cache directory for this cluster. By default, sparkrun uses the standard HuggingFace cache resolution (see [Troubleshooting](/getting-started/troubleshooting/#huggingface-cache-owned-by-root) for the full resolution order).

## Update a cluster

Modify hosts, description, or SSH user of an existing cluster:

```bash
sparkrun cluster update mylab --hosts 192.168.11.13,192.168.11.14,192.168.11.15
sparkrun cluster update mylab --user newuser
sparkrun cluster update mylab -d "Updated description"

# Add or remove individual hosts
sparkrun cluster update mylab --add-host 192.168.11.16
sparkrun cluster update mylab --remove-host 192.168.11.14
```

## Set as default

```bash
sparkrun cluster set-default mylab
```

When a default cluster is set, commands like `sparkrun run` use it automatically without needing `--cluster` or `--hosts`.

## Placement, state, and cache policy

Hardware inventory, per-host executor destinations, and live reservations determine
placement. Ordinary workloads reserve accelerators exclusively; a low engine memory
fraction does not automatically permit co-location. See [Schedulers](/advanced/schedulers/).
Workload metadata is shared across direct and daemon calls, while daemon operation
history is separate. Missing observations are not proof of idle capacity.
Cluster model validation/selection/provider settings and runtime cache cleanup are
covered in [Model Cache Management](/advanced/cache-management/).
