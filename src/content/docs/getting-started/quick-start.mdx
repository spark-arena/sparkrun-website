## Install

```bash
# Install uv if you don't have it
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install sparkrun and set up your cluster
uvx sparkrun setup
```

The setup wizard walks you through cluster creation, SSH mesh, and CX7 networking interactively. See the [Setup Wizard Walkthrough](/getting-started/setup-wizard/) for a detailed step-by-step guide.

## Use a saved cluster

Use the cluster created by the wizard as your default. A single-node cluster is
normal; for larger installations, put all nodes in the default and optionally
add smaller logical groups. See [Recommended Cluster Setups](/clusters/recommended-setups/).
Replace `mylab` below with the name you chose in the wizard.

```bash
sparkrun cluster set-default mylab
```

## Run a model

Let Sparkrun choose placement within the default cluster:

```bash
sparkrun run qwen3-1.7b-vllm

# Or select a different saved cluster
sparkrun run qwen3-1.7b-vllm --cluster mylab
```

sparkrun launches detached containers, follows startup logs, and returns after readiness and required hooks. Use `--no-follow` to wait quietly, `--follow` to keep watching after readiness, or `--no-ready-wait` for launch-only completion. **Ctrl+C detaches the observers and leaves the detached workload running.** See [run](/cli/run/#readiness-and-exit-status).

## Run multi-node (tensor parallelism)

With a cluster configured, scale across multiple DGX Sparks:

```bash
sparkrun run qwen3-1.7b-vllm --tp 2
```

Each DGX Spark has one GPU with 128 GB unified memory, so `--tp 2` splits the model across 2 nodes. See [Multi-Node Tensor Parallelism](/tutorials/multi-node/) for a full walkthrough.

## Inspect a recipe

```bash
sparkrun show nemotron3-nano-30b-nvfp4-vllm
```

This displays recipe details and a memory estimate. Unknown or lower-bound estimates do not establish fit; account for runtime allocation, KV cache, and observed host capacity. See [Memory-aware fit](/advanced/schedulers/#memory-aware-fit).

## Status, logs, and stop

The following output is illustrative; job IDs, addresses, images, and durations vary.

```bash
# Check what's running
$ sparkrun status

Job: @sparkrun-transitional/qwen3-1.7b-llama-cpp  [e0ed758410a2]  (1 container(s))
  solo       10.24.11.13 (ib: 192.168.11.13)          Up 45 minutes             ghcr.io/spark-arena/dgx-llama-cpp:latest
  logs: sparkrun logs e0ed758410a2
  stop: sparkrun stop e0ed758410a2
```

```bash
# Re-attach to logs (Ctrl+C is always safe) -- you can reference recipe or job ID
sparkrun logs @sparkrun-transitional/qwen3-1.7b-llama-cpp

# Stop a workload (shown here using job ID for unambiguous reference)
sparkrun stop e0ed758410a2
```

:::note
If you launched with `--tp` (modifying the recipe default), pass the same `--tp` flag to `stop` and `logs` so they resolve the same workload ID. Or, use the workload ID from `sparkrun status` directly:
:::
